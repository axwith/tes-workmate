# excel-to-report — 여러 엑셀로 원인 분석 보고서

원본 파일은 고치지 않는다. 정리본·결과는 모두 `reports/`에 새 파일로 만든다.

## 1. 자료 찾기
- 사용자가 경로를 주면 그것을 쓴다. 없으면 해당 업무 폴더의 `자료/` → `memory/scan/recent-files.csv`의 `copy` 열 → `00-inbox/` 순으로 `.xlsx`·`.xls`·`.csv`를 찾는다.
- 찾은 파일을 번호 목록(파일명·시트 수·행 수)으로 보여 주고 바로 진행한다. 묻지 않는다. 엉뚱한 파일이 섞였으면 사용자가 말할 때 뺀다.
- 파일이 10개를 넘으면 이름·기간으로 관련 있는 5~7개를 골라 쓰고, 고른 기준을 한 줄로 적는다.

## 2. 점검과 정리
Python으로 읽는다. Mac은 `python3`, 없거나 모듈이 없으면 Codex 런타임 Python(`~/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3`, Windows는 같은 위치의 `python.exe`)을 쓴다. 이 Python에는 openpyxl·pandas가 있다. 패키지를 설치하지 않는다. Python이 없으면 PowerShell이나 Codex 앱의 스프레드시트 기능으로 연다.

점검 항목(심각·주의·참고로 나눠 표로):
- 수식 오류(`#REF!`, `#VALUE!`, `#N/A`, `#DIV/0!`)
- 소계·합계가 세부 합과 다름, 비율이 분자/분모와 다름
- 같은 파일의 시트 간, 파일 간 같은 항목 숫자가 다름
- 병합 셀, 숨긴 행·열, 한 열에 숫자·글자 섞임, 오늘보다 뒤 날짜 행

정리본은 `reports/YYYY-MM-DD_<파일명>_정리.xlsx`로 저장한다: 병합 셀 풀고 값 채우기, "30.9%" 같은 글자를 숫자로, 날짜를 `YYYY-MM-DD`로, 소계·합계 행에 `행구분`(data/subtotal/total) 열 추가.

## 3. 엮어 보기와 문제 시점
- 일·주·월별, 라인·제품·거래처별로 집계하고, 파일마다 같은 지표(예: 생산실적의 생산량과 보고서의 생산량)를 나란히 비교한다.
- 문제 시점: 달성률·불량률·이익률 같은 핵심 지표가 평균에서 크게 벗어난 구간(±1.5σ), 전월 대비 ±20% 넘게 바뀐 시점. `references/`에 기준값이 있으면 그 기준을 먼저 쓴다.
- 기간·열 이름이 파일마다 다르면 맞춘 방식을 한 줄로 밝히고, 공통 기간만 쓴다.

## 4. 원인 가설
- 외부 요인 → 1차 영향 → 생산·품질 영향 → 실적 영향 순으로 이어 본다.
- 모든 주장에 출처 파일명·시트·근거 숫자를 붙인다. 숫자로 확인되지 않는 것은 "자료로 확인 안 된 가설"로 따로 적는다. 상관을 인과로 단정하지 않는다. 앞으로의 예측 숫자는 내지 않는다.
- 가설을 3~5줄로 보여 주고 이어서 보고서를 만든다. 사용자가 고치면 고쳐서 다시 만든다.

## 5. 보고서
- 기본은 PPT. 사용자가 워드나 엑셀을 원하면 그것으로. 문서 파일은 Codex 앱에 있는 프레젠테이션·문서·스프레드시트 만들기 기능으로 만든다. `references/`에 보고서 양식이 있으면 따른다.
- 구성(기본): 표지(제목·이름·소속·기준일, `AGENTS.md` 4장) → 결론 요약 3줄 → 핵심 지표 → 문제 시점 흐름 → 부문별 비교 → 원인 가설 → 할 일(즉시·단기·확인 필요).
- 차트 제목은 결론으로 쓴다(예: "2월 영업이익 79% 감소"). 문제 구간은 빨강, 정상은 파랑, 목표선은 점선.
- 저장: `reports/YYYY-MM-DD_<주제>_분석보고서.pptx`. 정리본 엑셀과 함께 위치를 알려 주고 연다(Windows `Start-Process`, Mac `open`).

## 6. 스스로 점검
- 보고서의 숫자를 정리본에서 다시 계산해 맞는지 본다. 틀리면 고친 뒤 보여 준다.
- 결과 끝에 "확인 필요" 항목(자료로 확인 안 된 가설, 파일 간 숫자 불일치)을 따로 적는다. 더 따져 볼 게 많으면 `cross-check` 방식으로 점검표를 붙인다.
