# foreign-matter-car — 이물 혼입 재발방지 대책서

원인 확정, 출하 중단·재개, 고객사 제출, 결재는 사람이 정한다. 이 스킬은 근거를 모으고 초안을 만든다. 원본은 고치지 않는다.

## 1. 자료 찾기와 읽기
- 사용자가 준 파일이 우선이다. 없으면 해당 업무 폴더의 `자료/` → `memory/scan/recent-files.csv`의 `copy` 열 → `00-inbox/` 순으로 찾는다(이름에 이물·SEM·EDX·초기보고·작업지시서·work-instruction).
- 초기보고서에서: 발생 일시, 라인, 제품, LOT, 검출 방식, 육안 소견(크기·색·질감·냄새).
- SEM-EDX에서: 원소별 wt%, 분석 조건, 샘플 ID. N(질소) 같은 원소가 없으면 "검출 한계 이하"인지 "측정 안 함"인지 구분한다.
- 빠진 필수 값은 한 번에 모아 번호 목록으로 묻고, 나머지는 그동안 진행한다.

## 2. 이물 DB 대조
- DB: `references/sem_edx_database.csv`(없으면 워크스페이스에서 `sem_edx_database.csv` 또는 이름에 "이물 DB"가 든 표). 열은 이름으로 읽는다(순서로 읽지 않는다).
- 1단계 거르기(원소 조합): 예) Zn+S 있고 N 없음 → 가황 천연고무 계열, Fe+Cr+Ni → 스테인리스, Cl 높음 → PVC 계열.
- 2단계 점수: 남은 후보와 원소별 wt% 비교. 허용 오차는 주요 원소(5% 초과) ±5wt%, 미량 원소(5% 이하) ±2wt%. 점수 = 허용 오차 안에 든 원소 수 / 비교한 원소 수. Python으로 계산한다(Codex 런타임 Python 가능, 설치 금지).
- 결과:
  - 1위 점수 0.8 초과이고 2위와 0.15 넘게 차이 → 후보 1건 + 비교표
  - 여럿이 비슷 → 상위 3건 비교표 + 무엇을 더 보면 가려지는지
  - 맞는 것 없음 → `UNMATCHED`. 추측하지 않고 "DB에 없는 이물입니다. 전문가 확인이 필요합니다."라고 쓴다.
- 이물 정체는 "추정"으로 표시하고, 사용자가 맞다고 하면 확정으로 바꾼다.

## 3. 작업지시서와 현장 비교
- 작업지시서에서 이물 정체와 이어지는 조항(예: 장갑, 보호구, 위생, 해당 공정)을 찾는다.
- 표: `| 항목 | 작업지시서 규정 | 현장 실태 | 어긋남 |`. 현장 실태를 모르면 "확인 필요"로 둔다.
- 규정에 아예 없는 것(교체 주기, 점검 절차, 변경 승인)도 따로 적는다.
- 작업지시서가 없으면 "작업지시서 없음 — 받으면 비교"라고 적고 나머지를 진행한다.

## 4. 원인 경로
`근본 원인 → 관리 원인 → 직접 원인 → 혼입 경로 → 검출` 순서로 한 줄씩. 근거 파일을 붙이고, 근거 없는 칸은 "확인 필요". 이 경로를 대책서 앞에 보여 주고 이어서 초안을 만든다. 사용자가 고치면 고쳐서 다시 만든다.

## 5. 대책서
`references/`나 업무 폴더에 회사 양식(예: 시정조치요구서 양식)이 있으면 그 순서를 따른다. 없으면 7절:
1. 사고 개요 — 일시·라인·LOT·이물(추정/확정)
2. 이물 동정 결과 — SEM-EDX 수치 + DB 비교표
3. 원인 분석 — 원인 경로, 규정 어긋남, 규정 빈틈
4. 영향 범위 — 보류(Hold) 수량, 납기 영향(모르면 확인 필요)
5. 재발방지 대책 — 즉시(1~3일)·단기(1~2주)·중장기(1개월), 줄마다 번호·담당·기한
6. 효과 확인 계획 — 대책별 방법·시기·판정 기준
7. 첨부 자료 목록 + 결재란(빈칸)

저장: `reports/YYYY-MM-DD_이물대책서.md`. 끝에 선택지: 1. 워드로 2. PPT로 3. 그대로. 워드·PPT는 Codex 앱의 문서·프레젠테이션 만들기 기능으로, 이 md를 그대로 옮겨 숫자가 어긋나지 않게 한다.
