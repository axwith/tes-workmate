# onboard — 업무 중심 온보딩 정본

## 공통 진행 원칙

- `memory/state.md`에 `prescan: 완료`가 없으면 prescan 절차부터 따른다.
- 열린 질문 대신 현재 확인한 내용을 먼저 보여 주고 번호 선택지를 준다.
- 이름·소속은 파일명, 문서 작성자, 메타데이터에서 추정하지 않는다. 사용자가 직접 입력할 때만 기록한다.
- 사전 스캔 자료와 업무 자료는 로컬 워크스페이스 밖으로 보내지 않는다.
- 기존 원본은 수정·이동하지 않는다. 새 폴더와 결과물만 만든다.
- 사용자가 승인하기 전에는 업무 결과물을 생성하지 않는다. 승인 전에는 계획만 저장한다.
- 각 단계가 끝나면 `memory/onboarding-state.md`에 선택값과 다음 단계를 기록한다. 기존 `memory/state.md`의 `onboard` 상태도 함께 갱신한다.

## 1. 사전 스캔 결과 확인

`memory/state.md`, `memory/work-map.md`, `memory/scan/recent-files.csv`, `memory/onboard-checklist.md`를 읽고 아래처럼 요약한다.

```
사전 스캔에서 찾은 업무 묶음:
1. [업무명] — [입력 자료] → [추정 결과물]
2. [업무명] — [입력 자료] → [추정 결과물]

자료 범위:
1. 스캔 결과와 사본을 그대로 사용
2. 업무 폴더를 추가로 지정
3. 이번 온보딩에서는 내 자료 대신 설치본의 가상 예시 자료로 연습
4. 기존 ChatGPT 대화에서 내 업무 가져오기
```

사용자가 번호를 고르면 선택을 기록한다. 아직 자료 범위를 모르면 2번을 고르게 하고 다음 단계에서 경로를 받는다. 4번이면 `.agents/skills/chatgpt-import/SKILL.md`를 열어 그 절차를 끝까지 따른 뒤(저장은 사용자가 승인한 것만) 이 파일의 2단계로 돌아온다. ChatGPT 대화를 읽지 못하면 그 스킬의 한 줄만 말하고 바로 2단계로 넘어간다.

3번이면 2단계(범위 카드)는 건너뛰고 3단계로 간다. 이때 원자료는 `.agents/skills/prescan/sample/pc/` 안의 가상 예시 파일뿐이다(품질 보고라면 `문서/품질보고/2026-11_검사결과.csv`와 `2026-10_월간품질보고.md`). 계획과 결과물에 이 파일 경로를 원자료로 적고, 숫자·날짜·사실은 이 파일에서만 가져온다. 새 가상 숫자를 지어내지 않는다. 파일에 없는 것은 `[확인 필요]`로 둔다. 4단계 업무 선택지도 사전 스캔에서 찾은 실제 업무가 아니라 이 예시 파일에서 나온 업무로 보여 준다: `1. 월간 품질 보고 — 검사 결과 CSV·전월 보고 → 업무 보고서(매월)`, `2. 협력사 견적 비교 — 협력사 견적 → 비교표`, `3. 반복 업무를 직접 입력`, `4. 아직 고르지 않음`.

## 2. 업무 폴더·자료 범위 확인

현재 업무 폴더, `자료/` 사본, `00-inbox/`, `memory/scan/recent-files.csv`의 범위를 보여 준다.

```
자료를 볼 범위를 고르세요.
1. 현재 업무 폴더와 사전 스캔 사본만
2. [발견된 업무 폴더]를 추가
3. 자료는 보지 않고 가상 일반 자료로만
```

사전 스캔이 찾은 동기화 폴더(OneDrive·SharePoint 동기화·구글 드라이브 등)는 `memory/scan/scan-roots.csv`에 `자동 발견`으로 남는다. 이 목록을 번호로 보여 주고 사용자가 고르게 한다(빼기·그대로 두기). 사용자가 뺀 폴더는 `memory/scan/scan-config.json`의 `exclude`에, 사용자가 입력한 폴더는 `include`에 넣는다. 사용자가 고르지 않은 폴더를 직접 더하거나 빼지 않는다. 바뀐 범위는 다음 새로 고침(sync)에 반영된다.

## 3. 이름·소속 직접 입력

파일에서 알아내지 않은 항목임을 짧게 설명하고 번호 선택지로 입력 방식을 제시한다.

```
이름과 소속은 직접 입력해 주세요.
1. 이름 / 소속을 한 줄로 입력 (예: 홍길동 / 품질팀)
2. 이름만 입력하고 소속은 나중에
3. 이름·소속을 지금 입력하지 않음
```

1번을 고르면 사용자가 보낸 값을 그대로 `AGENTS.md` 4장의 이름·소속에 기록하고 `memory/wiki/decisions/`에도 남긴다. 2·3번이면 이름을 만들거나 추정하지 않고 비워 둔다.

## 4. 현재 업무·반복 업무·보고 대상 확인

사전 스캔에서 발견한 업무를 실제 업무명으로 보여 준다.

```
지금 가장 먼저 맞출 업무를 고르세요.
1. [업무 1] — [결과물·주기]
2. [업무 2] — [결과물·주기]
3. 반복 업무를 직접 입력
4. 아직 고르지 않음
```

업무를 고른 뒤 다음 카드에서 각각 번호로 확인한다.

```
반복 주기:
1. 매일  2. 매주  3. 매월  4. 필요할 때
보고 대상:
1. 팀장/리더  2. 유관 부서  3. 고객/협력사  4. 직접 입력  5. 아직 미정
```

입력된 현재 업무, 반복 업무, 보고 대상을 `AGENTS.md` 4장과 상태 문서에 반영한다. 보고 대상의 실명은 사용자가 직접 입력한 경우에만 쓴다.

## 5. TES 회사·부서 맥락 확인

`memory/wiki/domain-context/`, `references/tes-glossary.md`, `AGENTS.md`의 TES 배경을 먼저 읽는다. 공개 자료로 미리 채운 회사 맥락과 사용자가 고른 부서 맥락을 구분해 보여 준다.

```
TES 맥락을 고르세요.
1. 공개 자료의 회사·제품 맥락만 사용
2. 회사 맥락 + 내 부서/팀을 직접 입력
3. 회사 맥락을 사용하지 않고 내 자료만 사용
```

2번이면 부서·팀·주요 제품/업무를 사용자가 직접 입력한다. 사내 조직명이나 고객 정보를 파일에서 추정하지 않는다.

## 6. 업무 결과물 종류 선택

첫 결과물의 종류를 아래에서 하나 고르게 한다.

```
첫 결과물 종류를 고르세요.
1. PPT 초안 — 핵심 메시지와 슬라이드 구성
2. 개발 문서 — 요구사항·설계·검토 항목
3. 시험 결과 요약 — 조건·결과·대조값·확인 필요 사항
4. 업무 보고서 — 결론·근거·다음 조치
```

사용자가 고른 종류와 자료 범위를 상태 문서에 기록한다. 파일을 만들지 않고 계획 단계로 넘어간다.

## 7. 첫 결과물 계획 작성 및 승인 게이트

선택한 업무와 결과물에 맞춰 `reports/YYYY-MM-DD_첫-결과물-계획.md`를 만든다. 계획에는 다음만 포함한다.

- 목적과 독자
- 사용할 자료 범위와 제외 범위
- 결과물 구성
- 확인할 숫자·근거·완료 기준
- 사람이 승인하거나 판단할 항목
- 생성하지 않을 개인정보·민감 자료

계획을 보여 주고 반드시 번호로 승인받는다.

```
첫 결과물은 이 계획대로 만들 수 있습니다.
1. 계획 승인 — 다음 메시지에서 결과물 생성
2. 계획 수정 — 수정할 항목을 번호로 선택
3. 보류 — 계획만 저장
```

1번을 사용자가 선택하기 전에는 PPT, 개발 문서, 시험 결과 요약, 업무 보고서를 생성하지 않는다. 승인 후에만 선택한 자료 범위와 업무 규칙을 사용해 결과물을 만들고 저장 위치를 알린다. 원자료에 없는 숫자나 사실은 넣지 않는다(자료 범위 3이면 가상 예시 파일이 원자료다).

## 완료 처리

모든 단계가 확정되면 `memory/onboarding-state.md`를 `완료`로 바꾸고 `memory/onboard-checklist.md`에서 처리한 항목을 체크한다. `memory/state.md`의 `onboard`는 `완료`로 기록한다. 아직 직접 입력하지 않은 이름·소속은 미완료로 남기되 작업을 막지 않는다.
