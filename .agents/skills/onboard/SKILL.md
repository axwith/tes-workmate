# onboard — 추정 확인하고 빈칸 채우기

prescan이 안 돼 있으면(`memory/state.md`에 `prescan: 완료`가 없으면) prescan부터 실행한다.


prescan이 이미 업무 폴더·`AGENTS.md` 4장·`references/`·위키를 추정값으로 채워 두었다. onboard는 처음부터 묻지 않고 **추정을 확인·수정하고 빈칸만 채운다.** 기준 목록은 `memory/onboard-checklist.md`.

## 원칙: 묻지 말고 보여 준다
처음 쓰는 사람은 질문을 받아도 무엇을 답해야 할지 모른다. 그래서 열린 질문을 하지 않는다. 먼저 결과를 보여 주고, 다음 행동은 번호 선택지로만 준다. 모르는 값은 추정값으로 진행하고 나중에 고친다.

## 1. 결과부터 열어 주기
- 상태 파일·스킬을 읽는 동안 아무 말도 하지 않는다("먼저 확인하겠습니다", "온보딩을 적용하겠습니다" 금지).
- 첫 응답에서 `reports/…_내-업무-한눈에.html`과 다음 회차 초안을 브라우저·기본 앱으로 연다(Windows: `Start-Process <경로>`). 열기가 막히면 링크만 준다.
- 첫 응답 형식(이 틀을 지킨다, 4~6줄):
  ```
  ○○님, 이번 주 업무 정리해 뒀어요. ← 이름을 모르면 "안녕하세요,"로
  [다가오는 일 한 줄: 예) 12월 첫째 주 품질 보고 초안도 지난달 형식으로 만들어 뒀습니다.]
  [업무 한눈에](링크) · [초안](링크)

  1. 〈업무 지도의 1순위 업무〉 마저 하기
  2. 〈2순위 업무〉
  3. 〈3순위 업무 또는 자료 더 넣기〉
  4. 다른 일 시키기
  ```
- 금지: "추정했습니다", "확인이 필요합니다", "파일명으로 봤습니다", "업무 공간 설정 확인하기" 같은 시스템 쪽 선택지. 선택지는 모두 이 사람의 실제 업무 이름으로 쓴다.
- 사용자가 "어떻게 알았어요?"라고 물으면 숨기지 않는다: "처음 열 때 최근에 쓰신 파일들을 읽고 정리해 뒀어요."

## 2. 일하면서 확정하기
- 사용자가 고른 일을 바로 한다. 추정값(`(추정: …)`)은 그대로 쓰고, 결과를 보여 줄 때 한 줄로만 짚는다: "보고 대상은 품질팀장님으로 넣었어요. 다르면 말씀만 해 주세요."
- 사용자가 고치지 않고 넘어가면 그 값을 확정하고(`(추정: …)` 삭제, 출처 "사용자 사용", 위키 `status: 확정`), 고치면 그대로 고친다.
- 빈칸이 꼭 필요할 때만, 그 일 안에서 번호 선택지로 묻는다(예: "기준을 어떻게 볼까요? 1. 지난달 대비 2. 목표치 대비"). 열린 질문은 하지 않는다.
- 틀린 업무 폴더·빠진 업무는 사용자가 말할 때 고친다. 먼저 묻지 않는다.

## 3. 다 쓰고 나면
- 일이 끝나면 `wrap`을 실행해 이번 교정을 후보 장부에 올린다.
- 남은 `(추정)`·빈칸은 `memory/onboard-checklist.md`에 남겨 두고, 이후 일을 하다가 자연스럽게 채운다.

## 4. 끝내기
- `memory/state.md` → `onboard: 완료`, 날짜.
- 바뀐 것 목록(만든 폴더, 고친 파일)을 보여 주고 "이제 업무 하나를 시켜 보세요. 끝나면 `wrap`으로 정리합니다"로 마친다.
- 나중에 다시 부르면 바뀐 부분만 확인한다(처음부터 다시 묻지 않는다).
