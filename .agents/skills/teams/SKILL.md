# teams — 팀즈 공유 파일 보기·사본 가져오기 (읽기 전용)

사용자가 팀즈·공유 자료를 말했을 때만 쓴다. 설치기·온보딩·다른 스킬에서 먼저 부르지 않는다. 연결이 안 되면 한 줄만 말하고 PC 파일로 계속한다(4장). 이 일 때문에 다른 일을 멈추지 않는다.

## 1. 실행 방법

- Windows: `powershell -NoProfile -ExecutionPolicy Bypass -File .agents/skills/teams/scripts/teams.ps1 <명령> [인자]`
- Mac: `<python> .agents/skills/teams/scripts/teams.py <명령> [인자]` — `<python>`은 `memory/env.md`의 `python:` 경로(없으면 Codex 런타임 Python). 둘 다 없으면 4장 한 줄로 끝낸다.
- 인터넷과 PC 사용자 폴더(로그인 정보 저장)를 써야 하므로 **권한 상승을 요청해 실행**한다. 승인 요청 이유: "팀즈(회사 Microsoft 365)에 로그인해 공유 파일 목록을 읽어 오려면 인터넷 연결과 로그인 정보 저장이 필요합니다. 읽기만 하고 보내거나 고치지 않습니다."
- 경로는 스크립트가 알아서 고른다: ① 팀즈 도구(CLI for Microsoft 365, `m365`)가 설치·로그인돼 있으면 그것으로 → ② 안 되면 기본 방식(스크립트가 Graph를 직접 호출) → ③ 둘 다 안 되면 4장 한 줄. 출력 형식은 어느 경로든 같다. `status`가 `팀즈 연결됨: … (도구: m365)`면 ①, 그냥 `팀즈 연결됨: …`이면 ②다.
- 설치는 `setup-m365` 하나뿐이다(1-1). 그 밖에 npm, Install-Module, pip로 따로 설치하지 않는다. 스크립트 자체는 PowerShell 5.1·Python 표준 기능만 쓴다.

### 1-1. 처음 쓸 때 팀즈 도구 설치(`setup-m365`, 한 번만)

- 언제: 사용자가 팀즈 기능을 처음 요청했을 때, 또는 "팀즈 도구 설치해 줘"라고 했을 때만. 설치기·온보딩·다른 스킬에서 미리 돌리지 않는다.
- 처음인지 보는 법: 설치 기록 `teams-setup.log`가 없으면 처음이다 — Windows `Test-Path "$env:LOCALAPPDATA\workmate\teams-setup.log"`, Mac `test -e ~/.workmate/teams-setup.log`. 기록이 있으면(성공이든 실패든) 다시 설치하지 않는다. 다시 하는 것은 사용자가 설치를 직접 요청할 때뿐이다.
- 실행: 권한 상승을 요청해 `setup-m365`를 한 번 실행한다. 명령 제한 시간은 6분 이상(스크립트가 5분에서 스스로 멈춘다). 승인 요청 이유: "팀즈 연결 도구(CLI for Microsoft 365)를 이 PC 사용자 폴더에 한 번 설치하려면 인터넷 연결과 사용자 폴더 쓰기가 필요합니다. 관리자 권한은 쓰지 않고, 팀즈에는 읽기만 합니다."
- 설치 위치(관리자 권한 없음, 사용자 폴더만): Windows `%LOCALAPPDATA%\workmate\node`(Node.js LTS, PC에 Node 22·24가 있으면 그것을 씀)·`%LOCALAPPDATA%\workmate\m365`, Mac `~/.workmate/node`·`~/.workmate/m365`. 진행 기록은 `teams-setup.log`에만 남고 화면에는 마지막 한 줄만 나온다.
- 결과가 "팀즈 도구를 설치했습니다: …" / "팀즈 도구가 이미 있습니다: …"이든 "팀즈 도구를 설치하지 못했습니다. 기본 방식으로 진행합니다."이든, **멈추지 말고 바로 원래 요청을 이어서 처리한다**(2장 로그인부터). 설치 실패를 사용자에게 길게 설명하지 않는다 — 그 한 줄이면 된다.
- 승인을 거절당하면 설치 없이 기본 방식으로 계속한다.

| 명령 | 하는 일 |
|---|---|
| `setup-m365` | 팀즈 도구 설치(1-1 조건에서만) |
| `status` | 연결 확인 |
| `login` / `login-wait` / `logout` | 로그인 시작 / 로그인 마무리(최대 90초 기다림, `-Wait 초`) / 이 PC의 로그인 정보 지우기 |
| `teams`, `channels <팀>` | 내 팀 목록, 그 팀의 채널 목록 |
| `files <팀> [채널]` | 채널 '파일' 탭(채널을 빼면 팀 전체 문서 라이브러리). 하위 폴더는 2단계까지(`-Depth 1~5`) |
| `shared`, `recent` | 나와 공유된 파일, 최근 파일 |
| `get <driveId> <itemId>` | 파일 사본을 `00-inbox/teams/`로(50MB까지) |
| `chats`, `chat-messages <채팅id 또는 이름>` | 채팅 목록, 최근 메시지(`-Top 20`, 최대 50) |
| `channel-messages <팀> <채널> -WithChannelMessages` | 채널 대화. 회사 관리자 승인이 있어야 된다 — 사용자가 채널 대화를 콕 집어 말할 때만 |

- 팀·채널·채팅은 이름 일부만 줘도 된다. 여러 개가 맞으면 후보가 한 줄로 나온다 → 번호 선택지로 묻는다.
- 목록 결과는 `memory/teams/<명령>-<시각>.csv`에 남고 화면에는 앞 40줄이 표로 나온다. `driveId`·`itemId`·`chatId`는 그 CSV에서 읽는다.
- Mac은 옵션을 `--depth`, `--top`, `--wait`, `--with-channel-messages`로 써도 된다.

## 2. 처음 연결(로그인)

1. `status`가 `[login-needed]`면 `login`을 실행한다.
2. 출력의 주소와 코드를 사용자에게 그대로 보여 준다: "브라우저에서 https://login.microsoft.com/device 에 들어가 코드 칸에 ABCD1234 입력 후 회사 계정으로 로그인하세요. 끝나면 '했어요'라고 말해 주세요." 코드는 15분 동안만 유효하다.
3. 곧바로 `login-wait`를 실행한다(명령 제한 시간 2분 이상). `[pending]`이면 사용자가 로그인을 마쳤다고 할 때 다시 실행한다.
4. "팀즈에 연결됐습니다"가 나오면 원래 요청을 이어서 한다. 다음부터는 저장된 로그인 정보를 스스로 갱신하므로 다시 로그인하지 않는다.
5. 브라우저에 "관리자 승인 필요(Need admin approval)"가 보였다고 하면 더 시도하지 않고 4장대로 한다.
6. 팀즈 도구가 설치돼 있으면 `login`이 그 도구로 로그인 코드를 받는다(뒤에서 기다리는 로그인). 도구가 코드를 못 내면 스스로 기본 방식 코드로 바꾼다. `login-wait`가 "다른 방식으로 로그인 코드를 다시 받았습니다."와 새 코드를 내면 그 새 코드를 2번처럼 다시 보여 주고 사용자가 마치면 `login-wait`를 한 번 더 실행한다.

로그인 정보는 PC 사용자 폴더에만 있다: 기본 방식은 Windows `%LOCALAPPDATA%\workmate\teams-token.json`, Mac `~/.workmate/teams-token.json`. 팀즈 도구는 자체 저장소(Windows 사용자 프로필의 `.cli-m365-*` 파일, Mac 키체인과 `~/.cli-m365-*`). 코드·토큰 값을 기록·보고서·위키에 쓰지 않는다. 공용 PC면 끝날 때 `logout`을 권한다(두 곳 모두 지운다).

## 3. 파일 찾기와 가져오기

1. 사용자가 말한 곳부터 본다: 팀·채널을 말했으면 `files <팀> <채널>`, "공유받은 것"이면 `shared`, 모르면 `recent` → `shared` → `teams` 순.
2. 찾은 파일 중 맞을 것 3~4개를 이름·수정일·수정한 사람과 함께 번호 선택지로 보여 준다. **사용자가 고른 파일만** `get`으로 가져온다. 폴더·목록 전체를 한꺼번에 내려받지 않는다.
3. 사본은 `00-inbox/teams/`에 들어가고, `00-inbox/teams/_목록.csv`에 원래 위치(webUrl)가 남는다. 팀즈의 원본은 고치지 않는다. 결과·보고서는 원래대로 `reports/` 등에 새 파일로 만든다.
4. 50MB가 넘거나 폴더면 가져오지 않는다고 나온다. 그 말을 한 줄로 전하고 다른 파일로 진행한다.
5. 가져온 파일로 바로 요청받은 일을 한다. 업무 폴더로 옮기는 것은 사용자가 원할 때 `inbox-sort`로 한다.

채팅은 사용자가 "채팅에서 받은 파일", "그 대화 내용"을 말할 때만 `chats` → `chat-messages`로 본다. 메시지 원문은 `memory/teams/` CSV에만 두고, 답에는 필요한 부분만 짧게 옮긴다.

## 4. 안 될 때 — 한 줄만 말하고 원래대로

스크립트가 `팀즈 연결이 안 됩니다. PC에 있는 파일로 진행합니다. [사유]`를 내면(로그인 전, 관리자 승인 필요, 회사망 차단, 403 등):

- 사용자에게는 **"팀즈 연결이 안 됩니다. PC에 있는 파일로 진행합니다."** 한 줄만 말한다. 대괄호 사유·오류 코드·영어 오류문은 말하지 않는다(사용자가 왜냐고 물으면 그때 사유를 쉬운 말로 답한다).
- 단, 사유가 `login-needed`이고 이번 대화에서 아직 로그인을 시도하지 않았으면 먼저 2장 로그인을 한 번 한다.
- 그다음 원래 흐름으로 계속한다: 해당 업무 폴더의 `자료/` → `memory/scan/recent-files.csv`의 `copy` 열 → `00-inbox/` 순으로 찾고, 없으면 `inbox-sort`로 PC 폴더에서 모은다.
- 같은 대화에서 재시도·우회(1-1 밖의 도구 설치, 브라우저 자동화, 다른 로그인 방법)를 하지 않는다. 팀즈 도구 → 기본 방식 전환은 스크립트가 이미 했다.
- 채널 메시지만 "관리자 승인이 있어야" 나오면 그 기능만 빼고 파일·채팅은 그대로 쓴다.

## 5. 보안

- 읽기만 한다. 메시지 보내기·파일 올리기·고치기·지우기 명령은 없다.
- 고객사 자료·개인정보·인사·계약 파일은 사용자가 고른 것만 가져오고, 목록을 보여 줄 때도 필요한 것만 추린다.
- 가져온 파일과 `memory/teams/` 목록을 외부 사이트·다른 사람에게 보내지 않는다.
- 회사 IT 정책(관리자 승인, 접속 차단)을 우회하지 않는다.
