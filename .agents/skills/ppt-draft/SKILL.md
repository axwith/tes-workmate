# ppt-draft — 고정 템플릿 기반 PPT 초안

원본 자료를 수정하지 않는다. TES 내부 교육용 공통 템플릿을 사용한다. 참가자 개인정보·기밀정보를 임의로 넣지 않고, 사용자가 고른 자료만 쓴다. 결과물은 초안이며 최종 판단과 배포 전 검토는 사람이 한다.

## 1. 자료와 업무 유형 확인

- 사용자가 경로를 주면 그 자료를 우선 읽는다. 경로가 없으면 해당 업무 폴더의 `자료/` → `memory/scan/recent-files.csv`의 `copy` 열 → `00-inbox/` 순으로 찾는다.
- 자료가 없으면 가상 TES 예시 자료로만 계획하고, 실제 회사·고객·개인정보를 만들지 않는다.
- 업무 유형을 다음 중 하나로 분류한다.
  - 연구개발: 개발 검토자료 / 시험 결과 요약 / 실험 계획
  - 혼합직무: 고객 대응 / IR / 영업 / 사업기획 보고
- 공통 단계는 `업무 파악 → 기획 → 만들기 → 검토 → 개선`이다. 각 단계에서 사람이 확인할 항목을 남긴다.

## 2. 승인 전 계획 게이트

기존 자료를 읽어 PPT 초안을 요청받았으면 파일을 만들기 전에 아래 계획을 먼저 보여 준다. 계획 파일만 `reports/YYYY-MM-DD_<주제>_PPT-계획.md`로 저장할 수 있다.

1. 독자: 누구에게 보여 주는가
2. 목적: 어떤 판단·공유를 돕는가
3. 자료: 사용할 파일·시트·페이지와 제외할 범위
4. 목차: 슬라이드별 제목·핵심 메시지·근거
5. 표시 규칙: 숫자·출처·원자료 경로·확인 필요 항목
6. 완료 기준: 원자료 대조, 누락·모순 점검, 사람 승인 항목

반드시 다음 선택지를 제시한다.

1. 계획 승인 — 다음 요청에서 PPTX 생성
2. 계획 수정 — 수정할 항목 선택
3. 보류 — 계획만 저장

승인 전에는 PPTX, PPTX 미리보기 이미지, 차트 파일을 만들지 않는다.

## 3. 승인 후 만들기

- 승인받은 계획과 자료만 사용해 `reports/YYYY-MM-DD_<주제>_초안.pptx`로 저장한다.
- 공통 템플릿은 `tes-template.pptx`(14장)이고 생성기는 `scripts/build_template.py`의 `Deck` 클래스다. 초안은 이 클래스로 만든다. 디자인 규칙은 `DESIGN-GUIDE.md`를 따른다. Python `python-pptx`가 없으면 설치하지 말고 사용자에게 준비 필요를 알린다.
  ```python
  import sys; sys.path.insert(0, '.agents/skills/ppt-draft/scripts')
  from build_template import Deck
  d = Deck('.agents/skills/ppt-draft/assets')
  d.source = '출처: 2026-09~11 수입검사결과.xlsx  |  기준일 2026-11-23'   # 모든 본문 장 하단
  d.cover('9~11월 수입검사\n불량 분석', '품질팀장 보고', '품질팀 · 김민수 · 2026. 11. 23.')
  d.section = ('01', '월별 불량률 추이')        # 머리말에 나오는 섹션 번호·이름
  d.chart('월별 불량률 지속 감소', '불량률 = 불량 수 ÷ 검사 수 (%)', ['9월', '10월', '11월'], [2.47, 2.34, 2.02],
          chart_head='월별 불량률 (%)',
          points=['9월 2.47%에서 10월 2.34%, 11월 2.02%로 두 달 연속 낮아졌습니다.',
                  '9월 대비 11월은 0.45%p 낮고, 불량 수는 40건에서 28건으로 12건 줄었습니다.'],
          band='불량률이 두 달 연속 낮아져 11월 2.02%로 3개월 중 최저')
  found = d.save('reports/YYYY-MM-DD_<주제>_초안.pptx')   # 고칠 곳 목록을 출력한다
  ```
- 예시 덱 전체 코드는 `examples/수입검사_불량분석.py`에 있다. 장표 고르기와 본문 분량은 이 예시를 기준으로 삼는다.
- 본문 장 전에 `d.section`을 정하거나 `section_divider`를 쓴다. 두 줄이 필요한 글은 `\n`으로 의미 단위에서 직접 나눈다(한 단어만 다음 줄로 떨어지지 않게).
- 고칠 곳은 생성 스크립트의 `Deck` 호출 인자(글)를 고친 뒤 스크립트를 다시 실행해서 고친다. 저장된 PPTX의 글을 python-pptx로 직접 바꾸지 않는다(글자 크기·색이 사라진다. `save()`가 이것도 잡는다).
- 파레토처럼 PPT 차트로 어려운 그래프는 `scripts/charts.py`의 함수(`pareto` 등)로 원자료 값을 넣어 그린다. `examples/`의 그림을 복사해 쓰지 않는다.
- `save()`가 출력한 "고칠 곳"이 0건이 될 때까지 글을 줄이거나 장을 나눠 다시 만든다. 넘친 글은 글자 크기를 줄이지 말고 문장을 줄인다. 견본 문구(입력하세요, 한 줄로, 섹션 이름 등)가 남으면 실제 내용으로 바꾼다.
- 쓸 수 있는 장표(모두 TES IR 구조: 머리말 · 짧은 제목 · 패널 · 결론 띠): `cover` 표지, `agenda` 목차, `section_divider` 섹션, `kpi` 수치 카드+해석, `chart` 차트+주요 내용, `table` 표+주요 내용, `two_column` 설명+그림(그래프 PNG·도식), `image_pair` 그림 두 개(생성 이미지+그래프), `two_panels` 패널 두 개(실적/전망 등), `statement` 번호 설명+핵심 수치, `three_points` 카드 3개, `process` 단계, `timeline` 일정, `comparison` 전후 비교, `conclusion` 결론·확인 내용·다음 단계, `closing` 마무리. 계획의 슬라이드마다 가장 맞는 장표 하나를 고르고, 같은 장표를 연달아 3번 이상 쓰지 않는다. 한 장을 비워 두지 말고 패널마다 설명을 채운다.
- 글쓰기는 아래 "3-2. 장표 글쓰기"를 따른다.
- 색: 흰 바탕, 글자 진회색, 구조는 회색·TES 네이비, 강조는 TES 블루 `#0063A8` 한 곳만. 차트는 강조할 막대 하나만 파랑, 나머지는 회색(`highlight`로 지정).
- 사진은 표지·섹션·마무리에만 있다. 본문 장에는 사진·장식 그래픽을 넣지 않고, 필요하면 `assets/icons/`의 선 아이콘(Lucide)만 쓴다. 로고·출처·쪽번호 위치는 생성기가 고정한다.
- 출처·원자료는 본문을 방해하지 않도록 장표 하단에 작게 배치한다. 8~9pt, 좌측 또는 우측 정렬, `출처: ... | 원자료: ...` 형식을 사용한다. 표지·섹션·Thank you는 footer를 생략할 수 있다. 확인하지 못한 숫자는 `확인 필요`로 표시한다.
- 차트는 원자료에 있는 값만 사용한다. 값이 없으면 차트 대신 자리표시자와 확인 필요를 넣는다.

## 3-1. 그래프와 이미지 만들기

계획의 슬라이드마다 "글로 충분한가 / 그래프가 필요한가 / 이미지가 필요한가"를 정해 계획 표에 적는다.

- **그래프**: 원자료 숫자로 그린다. 막대·선·누적 막대는 PPT 안 차트(`Deck.chart`, 편집 가능)로 넣는 것을 먼저 쓴다. 파레토(막대+누적 비율선), 산점도, 분포처럼 PPT 차트로 어려운 것은 Python(matplotlib)으로 PNG를 그려 `reports/<주제>_그림/`에 저장한 뒤 `two_column` 장의 그림 칸에 넣는다. 색은 회색 `#C9CFD8`, 강조 1개만 TES 블루 `#0063A8`. 격자선·테두리·범례 없이 값을 막대 끝에 직접 적는다. matplotlib 그림은 `figsize=(11, 8)`, `dpi=200`, 글자 24pt 이상(막대 값 28pt)으로 그린다. `scripts/charts.py`의 `pareto()`가 이 규칙대로 그린다. PPT에 넣으면 줄어들어 작은 글자는 읽히지 않는다. 웨이퍼 맵·산점도도 같다 — 저장은 `plt.savefig(..., bbox_inches='tight', pad_inches=0.1)`로 바깥 여백을 잘라 그림이 패널을 채우게 하고, 한 그림에 작은 그래프를 여러 개 넣지 말고 장을 나누거나 `image_pair`로 두 개씩 놓는다. 저장한 뒤 PNG를 열어 글자가 읽히는지 본다. 그림 위 제목은 넣지 않는다(장 제목이 대신한다). 축 제목·단위·기간을 반드시 적고, 그린 숫자를 원자료 3곳과 대조한다.
- **이미지**: 표지·섹션·마무리처럼 분위기 사진이 필요한 자리, 또는 개념도·공정 흐름 그림이 필요한 자리에만 만든다. 본문 장마다 장식 이미지를 넣지 않는다. 품앗이 플러그인의 `pumasi-image` 스킬로 생성한다(설치: 1교시 플러그인 단계에서 `pumasi-codex`). 프롬프트에는 "흰 배경 또는 네이비, 파랑 포인트, 글자·로고 없음"을 넣고, 같은 덱의 이미지는 첫 장을 기준 이미지로 물려 스타일을 맞춘다. 표지 그림은 기본 견본(`assets/cover-wafer.png`·`cover-fab.png`, 흰 배경 세로 4:5)을 쓰고, 새로 만들 때도 표지 배경색(흰색)에 맞춰 세로 4:5로 생성한다. 다른 그림을 잘라 표지에 넣지 않는다. 생성 이미지는 `reports/<주제>_그림/`에 저장하고 footer에 `이미지: AI 생성`을 적는다.
- 글로 설명하기보다 모습을 보여 주는 편이 빠른 내용(불량 유형의 생김새, 장비·부품·공정 개념)은 `pumasi-image`로 그림을 만들어 `image_pair`(그림+그래프) 또는 `two_column`의 그림 패널에 넣는다. 그림 속 한글 라벨은 2~4자로 짧게 지정하고, 생성 뒤 글자를 원문과 대조한다. 그림 설명 칸에 `이미지: AI 생성`을 적는다. 그림만 두지 말고 그림마다 아래에 무엇을 봐야 하는지 짧은 설명 1~2개를 붙인다(`image_pair`의 네 번째 값). 예: 불량 유형 4종 그림(`examples/수입검사_불량분석.py`의 2장).
- `pumasi-image`가 없거나 실패하면 이미지 없이 아이콘(`assets/icons/`)으로 대신하고, 그 사실을 결과 보고에 한 줄로 적는다.
- 그래프·이미지를 만들기 전에 어떤 장에 무엇을 넣을지 계획에서 승인받는다. 승인 뒤 생성한다.

## 3-2. 장표 글쓰기

제목과 본문의 역할을 나눈다. 제목은 핵심만 짧게, 본문은 그 핵심을 설명하는 문장으로 쓴다. 제목만 넘겨 봐도 흐름이 잡히고, 본문을 읽으면 근거와 뜻이 이해되어야 한다.

- **표지 제목**: 보고서 이름이다. `기간 + 대상 + 보고 종류` 형식으로 쓰고 수치·결론을 넣지 않는다. 예: `9~11월 수입검사 불량 분석`, `3분기 고객 클레임 현황 보고`. 부제는 보고 대상이나 목적 한 줄(`품질팀장 보고`).
- **본문 제목**: 그 장의 핵심만 명사형으로 짧게 끝낸다. 한 줄, 한글 20자 안쪽. 수치·근거·조건은 제목에 넣지 않는다.
- **글 분량**: 본문 장 하나에 설명 2~3개. 카드·차트·표에 이미 보이는 숫자를 설명에서 다시 나열하지 말고, 숫자가 말하는 뜻과 비교만 쓴다.
- **본문 설명**: 제목을 뒷받침하는 내용을 설명형 문장으로 쓴다. 수치, 비교 대상, 원인 후보, 뜻을 여기에 적는다. 항목마다 `무엇이 → 얼마나(수치·비교) → 그래서 무슨 뜻인지`까지 쓴다. 항목 하나는 두 줄 안쪽, 장 하나에 3~4개. 짧은 단어 나열로 끝내지 않는다. 확인하지 못한 원인은 "~로 보이나 확인 필요"처럼 단정하지 않는다.
- **결론 띠**: 장 아래 네이비 띠는 그 장의 결론을 설명하는 한 문장이다. `무엇이 어떻다 + 그래서 무엇을 본다/한다`까지 쓴다. `원인은 미확정`, `확인 필요`처럼 꼬리표만 쓰지 않는다. 예: `PM과 레시피 변경이 같은 기간에 겹쳐, 두께 변화가 어느 쪽 때문인지는 동일 조건 재시험으로 가려야 함`. 18자보다 짧으면 점검기가 경고한다.
- **강조 수치**: 하나만 크게(차트 옆·큰 숫자 칸) 두고, 나머지 수치는 본문 설명 안에 넣는다.
- **줄바꿈**: 두 줄이 되는 글은 의미 단위에서 `\n`으로 직접 나눈다. 한 단어만 다음 줄로 떨어지지 않게 한다.

| 자리 | 나쁜 예 | 좋은 예 |
|---|---|---|
| 표지 | 수입검사 불량률은 9월 2.47%에서 11월 2.02%로 낮아졌다 | 9~11월 수입검사 불량 분석 |
| 제목 | 월별 불량률은 2.47% → 2.34% → 2.02%로 낮아졌다 | 월별 불량률 지속 감소 |
| 본문 | 9월 2.47% | 불량률이 9월 2.47%에서 11월 2.02%로 두 달 연속 낮아졌습니다. |
| 제목 | 치수·도금·스크래치가 전체 불량의 84.47%를 차지한다 | 불량 상위 3개 유형에 집중 |
| 본문 | 치수 31건 | 치수 불량이 31건으로 가장 많고, 도금과 스크래치가 각 28건으로 뒤를 잇습니다. |
| 제목 | 불량률 하락이 공정 개선인지 검사 구성 변화인지 추가 확인이 필요하다 | 불량률 하락 원인 확인 필요 |
| 본문 | 검사수 변동 | 월별 검사 수가 1,617건에서 1,385건으로 줄어, 불량률 하락이 공정 개선 때문인지 검사 구성 변화 때문인지 아직 구분되지 않습니다. |

## 4. 검토와 개선

- 원자료와 슬라이드의 제목·숫자·단위·기간·출처를 대조한다.
- 개발·시험 결과는 조건, 결과, 대조값 3개, 해석과 확인 필요를 구분한다. 원인을 확정하지 않는다.
